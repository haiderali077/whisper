# Feature branch workflow

- Before implementing a new feature, create a new descriptive branch such as `feat/messaging-load-tests`, even when the user does not explicitly ask for a branch.
- Prefer an up-to-date `main` as the starting point when appropriate. Inspect the working tree first and preserve existing changes; never reset or discard work to create a branch.
- Continue an already-started feature on its existing branch rather than creating a branch for each follow-up edit or bug fix within that feature.
- Do not commit, push, or merge into `main` unless the user requests those actions.
